# TCS bot tools — implementation spec

The demo bot has four tools, all backed by Postgres (`postgres demo`). Their
JSON is generated by `scripts/build_tcs_workflows.py`.

All SQL below uses the TCS tables: `tcs_leads`, `tcs_events`,
`tcs_crm_units`, `tcs_crm_viewing_slots`, `tcs_crm_viewing_bookings`,
`tcs_crm_conversation_state`. `whatsapp_id` is always `tg:<chat_id>` and comes
from `Normalize Message`, never from the model.

## 1. search_units (Postgres tool)

Inputs from the model: `beds` (int, optional), `max_rent` (int, optional),
`pets` (bool, optional).

```sql
SELECT id AS unit_id, building, unit_number, beds, baths, rent_usd, deposit_usd,
       available_from, pets_policy, description
FROM tcs_crm_units
WHERE status = 'available'
  AND deleted_at IS NULL
  AND ($1::int IS NULL OR beds = $1)
  AND ($2::int IS NULL OR rent_usd <= $2)
  AND ($3::bool IS NOT TRUE
       OR lower(COALESCE(pets_policy, '')) NOT LIKE 'no pets%')
ORDER BY rent_usd ASC
LIMIT 5;
```

Agent-facing description: “Search available apartments. Use for any question
about availability, price, or building.”

## 2. get_slots (Postgres tool)

Goal: return up to 3 open future viewing slots from `tcs_crm_viewing_slots`
within 7 days starting at `from_date` (ISO 8601 with timezone +
`America/New_York` display). Viewing hours are Monday-Friday 10:00-17:00 ET;
weekends have no slots.

Optional inputs from the model:
- `$1` `unit_id` (UUID string or empty)
- `$2` `from_date` (`YYYY-MM-DD`, default today in `America/New_York`; an
  empty or malformed value falls back to today, and a past date is clamped to
  today)

An empty result is NOT a handoff reason: the bot explains the weekday
10:00-17:00 ET schedule and retries with a later `from_date`. A weekend
`from_date` still returns the following weekdays because the window is 7 days.

```sql
WITH p AS (
  SELECT GREATEST(
           CASE WHEN COALESCE($2::text, '') ~ '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'
                THEN ($2::text)::date
                ELSE (now() AT TIME ZONE 'America/New_York')::date END,
           (now() AT TIME ZONE 'America/New_York')::date
         ) AS from_date
)
SELECT s.id AS slot_id,
       to_char(s.starts_at AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS"Z"') AS starts_at,
       to_char(s.starts_at AT TIME ZONE 'America/New_York', 'Dy Mon DD, HH12:MI AM') || ' ET' AS local_time,
       s.duration_min,
       s.unit_id
FROM tcs_crm_viewing_slots s, p
WHERE s.status = 'open'
  AND s.starts_at > now()
  AND s.starts_at >= p.from_date::timestamp AT TIME ZONE 'America/New_York'
  AND s.starts_at < (p.from_date + 8)::timestamp AT TIME ZONE 'America/New_York'
  AND (NULLIF($1::text, '')::uuid IS NULL
       OR s.unit_id IS NULL
       OR s.unit_id = NULLIF($1::text, '')::uuid)
ORDER BY s.starts_at ASC
LIMIT 3;
```

Agent-facing description: “Fetch up to 3 open viewing slots in the 7 days from
`from_date` (default today). Viewings are Monday-Friday 10:00-17:00 ET. Offer
ONLY slots returned by this tool; never invent dates or times. An empty list
means no viewings in that window — explain the weekday schedule and retry with
a later `from_date`, do not hand off.”

## 3. book_viewing (Postgres tool)

Inputs:
- `$1`: `whatsapp_id` (from `Normalize Message`, NOT from the model)
- `$2`: `slot_id` (UUID returned by `get_slots`)
- `$3`: `unit_id` (optional UUID returned by `search_units`, or empty string)
- `$4`: `client_name` (optional client name)
- `$5`: `client_phone` (optional client phone number)

Calls the atomic Postgres function `tcs_crm_book_viewing(...)` which books the
slot, updates `tcs_leads` and writes `trial_booked` / `trial_rescheduled` to
`tcs_events`.

```sql
SELECT result, booking_id
FROM tcs_crm_book_viewing(
  $1::text,
  $2::uuid,
  NULLIF($3::text, '')::uuid,
  NULLIF($4::text, ''),
  NULLIF($5::text, '')
);
```

## 4. handoff_to_human (Postgres tool)

Agent-facing description: “Hand the conversation to the office team. Call ONLY
when the person explicitly asks for a human, complains or reports an
unresolvable problem, after two failed tool calls in a row, or for an
out-of-scope/accommodation/emergency request. Never call it for an empty slot
list, an unknown answer, or a vague request.”

Inputs:
- `$1`: `whatsapp_id` (from `Normalize Message`, NOT from the model)
- `$2`: `reason` (string, optional)

```sql
WITH upd AS (
  UPDATE tcs_leads
  SET status = 'HANDOFF', updated_at = now()
  WHERE whatsapp_id = $1
  RETURNING whatsapp_id
), ev AS (
  INSERT INTO tcs_events (whatsapp_id, event_type, payload)
  SELECT $1, 'transferred_to_manager', jsonb_build_object('reason', NULLIF($2, ''))
  WHERE EXISTS (SELECT 1 FROM upd)
)
SELECT 'handed_off' AS result;
```

The CRM mirrors `HANDOFF` into notifications/autopause via `sync_worker`, so
the bot does not call the CRM API.

## Notes

- Possible results from `book_viewing`: `booked`, `slot_taken`, `slot_not_found`,
  `slot_in_past`, `unit_mismatch`, `lead_not_found`.
- `slot_taken` / `slot_in_past` must be handled by the model: apologize, call
  `get_slots` again, and offer other open slots (or `handoff_to_human` if none).
- Stage values used by the bot: `NEW_INQUIRY`, `QUALIFIED`, `VIEWING_SCHEDULED`,
  `VIEWING_DONE`. Terminal outcomes: `LEASED`, `LOST`.
- Reminders query `tcs_leads` joined with `tcs_crm_units` (`deleted_at IS NULL`)
  on `lead_data->>'unit'`.
- Credential in n8n: `postgres demo`, `tcs demo bot`, `OpenRouter account`.
